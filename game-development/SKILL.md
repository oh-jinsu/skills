# 게임 개발 및 모델링 지침

게임 기획·개발·화면 구성·캐릭터 및 배경 모델링 작업에 적용한다. 사용자가 해당 작업에서 명시적으로 다른 방향을 요청하면 그 요청을 우선한다.

## 1. 조사하고, 작게 만들고, 직접 검증한다

- “어떤 게임과 비슷하게 만들어줘”라는 요청을 받았다고 곧바로 코딩하거나 모델링하지 않는다. 먼저 외부 자료와 실제 레퍼런스를 조사한다. 모델의 기억이나 장르에 대한 일반적인 인상만으로 구현 방향을 정하지 않는다.
- 게임은 실제 플레이 영상·스크린샷·개발자 자료 등을 확인한다. 모델링은 대상의 여러 각도와 형태, 동시대 게임의 실제 모델·텍스처 사례를 확인한다. 자료에서 관찰한 사실과 추정은 구분한다.
- 분위기나 색상만 참고하지 않는다. 게임에서는 이동 속도와 가속, 점프 궤적, 공중 제어, 카메라, 충돌, 공간 크기와 동선 등 이번 작업에 필요한 요소를 분석한다. 모델에서는 실루엣, 비례, 면 구성, UV와 텍스처 표현을 분석한다.
- 구현 전에 참고 자료의 출처 링크, 관찰한 특징, 이번 단계에 적용할 내용을 짧게 정리한다. 자료를 열어보지 않고 조사한 것처럼 쓰지 않는다. 외부 자료에 접근할 수 없으면 한계를 알리고, 조사 없이 큰 구현을 진행하지 않는다.
- 한 번에 많은 시스템이나 에셋을 만들지 않는다. 이번 단계에서 확인할 핵심을 하나 정하고, 그것을 평가하는 데 필요한 최소 범위만 구현한다. 요청에 없는 전투·수집·맵·메뉴·서사 등을 한꺼번에 추가하지 않는다.
- 예를 들어 Pseudoregalia를 참고하는 경우, 관련 플레이 자료에서 이동과 점프를 먼저 분석하고 작은 테스트 공간에서 조작감을 확인한다. 이후 벽차기, 카메라, 탐험 동선 등을 단계적으로 다룬다.
- 테스트용 블록아웃은 공간과 조작을 검증하는 용도로 사용할 수 있다. 임시 형태를 완성된 캐릭터나 최종 아트로 제출하지 않는다.
- 각 단계는 실제 실행과 플레이 또는 모델 뷰어 확인으로 검증한다. 스크린샷의 겉모습만으로 조작감이나 완성도를 판단하지 않는다. 사용자가 확인할 수 있는 작은 결과와 남은 문제를 제시하고, 피드백을 받기 전에 다음 단계까지 확대하지 않는다.

## 2. 게임 화면을 꽉 채우고, 플레이로 설명한다

- 플레이 중 게임 화면은 사용 가능한 창 영역 전체를 채운다. 브라우저 게임이라면 뷰포트를 채우고 창 크기가 바뀌어도 유지한다. 브라우저 전체 화면 모드로 강제 전환해야 한다는 뜻은 아니다.
- 게임을 소개용 웹페이지나 대시보드 안의 작은 카드로 배치하지 않는다. 설명 패널, 장식용 여백, 거대한 제목, 배지, 카드, 테두리 등으로 플레이 영역을 줄이지 않는다.
- 있어 보이기 위한 연출과 정보 배치를 금지한다. 빈 공간이 있다는 이유로 설명을 채우지 않는다. 기술 스택, 개발 의도, 기능 목록, 프로젝트 소개를 게임 화면에 상시 표시하지 않는다.
- 닌텐도 게임을 참고하는 방향으로 UI를 최소화하고, 조작·반응·공간 배치·시각 및 청각 피드백으로 플레이 방법을 알린다. 특정 작품을 조사하지 않고 “닌텐도 스타일”이라는 말만 근거로 디자인하지 않는다.
- HUD는 지금 플레이하는 데 꼭 필요한 정보만 표시한다. 조작 안내는 필요한 순간에 짧게 보여주고, 상세 도움말과 설정은 사용자가 열 수 있는 메뉴로 둔다.
- 개발 문서와 검증 결과는 README나 별도 문서에 기록한다. 디버그 표시가 필요하면 개발용으로 명시적으로 켜고 끌 수 있게 하고 기본 플레이 화면에서는 숨긴다.
- 화면 검증에서는 플레이 영역이 실제로 창을 채우는지, UI가 시야와 조작을 방해하지 않는지, 설명을 읽지 않고도 다음 행동을 알아볼 수 있는지 확인한다.

## 3. 로우폴리 메시와 음영을 담은 텍스처를 기본으로 한다

- 기본 미술 방향은 NDS / Nintendo 64 / PSX 계열을 참고한 단순한 로우폴리 모델과, 기본 음영을 베이킹한 저해상도 텍스처의 조합이다. 기종마다 표현이 다르므로 작업에 맞는 실제 사례를 먼저 선정한다.
- 구·박스·원기둥 같은 기본 도형을 눈에 띄게 이어 붙여 장난감처럼 보이는 캐릭터나 주요 에셋을 만들지 않는다. 도형을 시작점으로 쓰더라도 최종 형태는 의도한 실루엣·비례·면 흐름을 가진 메시로 다듬는다.
- 폴리곤 수가 적다는 이유로 형태 연구를 생략하지 않는다. 적은 면으로도 머리와 몸의 비례, 관절, 의상과 소품의 특징, 캐릭터의 실루엣을 읽을 수 있어야 한다.
- UV를 구성하고 기본 명암·접촉 음영·재질 구분이 담긴 텍스처를 사용한다. 단색 재질과 실시간 조명만으로 최종 표현을 대신하지 않는다. 필요하면 베이킹한 음영 위에 수작업 보정을 더한다.
- 텍스처 해상도와 폴리곤 예산은 실제 레퍼런스와 게임 카메라 거리에서 정한다. 고해상도 광택 재질이나 과한 후처리로 형태와 텍스처의 부족함을 가리지 않는다.
- 완성도를 정면 한 장으로 판단하지 않는다. 정면·측면·후면·사선 및 실제 게임 카메라에서 실루엣, 관절 연결, 텍스처 이음새와 음영을 확인한다. 애니메이션이 있다면 움직이는 상태에서도 확인한다.
- 레퍼런스는 분석에 사용한다. 기존 게임의 캐릭터·모델·텍스처를 그대로 복제하거나 무단 전용하지 않고 새로운 에셋으로 제작한다.

## 4. 캐릭터 생성과 부위별 텍스처 페인팅

캐릭터 모델 생성·리텍스처 작업에서는 [캐릭터 모델링·페인팅 절차](references/character-modeling-texturing.md)를 읽고 적용한다. 기존의 비례와 형태가 승인되었다면 이를 기준으로 진행한다.

- 디자인 이미지를 먼저 맞추고, 리깅용 캐릭터는 팔다리가 분리되어 보이는 T 포즈로 생성한다. Tripo에서 선택한 메시를 다운로드한 뒤 로컬에서 텍스처를 작업하는 흐름을 기본으로 삼는다. 기존 다운로드를 우선 재사용하고 유료 생성·내보내기를 불필요하게 반복하지 않는다.
- 페인팅 전에 머리카락 / 얼굴·귀·턱·목 / 옷 / 손 / 다리 / 신발 등을 영구적인 **면 영역**으로 나눈다. 재질 슬롯 또는 FACE 속성으로 마스크를 저장하고 필요한 경계에 Seam을 표시한다. Mark Seam만으로 칠할 영역이 제한되지는 않는다.
- 텍스처 작업에서는 승인된 형상·비례·삼각형 수·UV를 유지한다. 사용자가 새로 칠하라고 하면 이전 페인팅을 재사용하지 않는다. 승인된 디자인과 메시, 부위 마스크는 계속 사용할 수 있다.
- 실제 텍스처가 적용된 메시를 **6면 + 위·아래 사선 8방향**에서 확인하고 연속 회전한다. 정수리, 머리카락 안쪽, 귀·턱·목, 겨드랑이, 치마 안쪽, 다리 사이, 밑창을 점검한다. 정면과 후면 이미지가 좋아 보이는 것만으로 완료하지 않는다.
- 수정 가능한 Blender 파일, 텍스처가 포함된 GLB, 컬러 텍스처, 재현용 설정을 남긴다. 실제 확인한 결과와 형상 자체의 한계를 구분한다.

## 단계별 완료 기준

1. **조사:** 실제로 확인한 자료 링크와 이번 작업에 적용할 관찰 내용이 있다.
2. **범위:** 이번에 검증할 핵심 하나와 확인 방법이 명확하다.
3. **구현:** 그 범위만 구현하고, 임시 요소를 최종 결과와 구분했다.
4. **검증:** 실제 플레이 또는 여러 각도의 모델 확인을 수행하고, 확인한 것과 미확인 사항을 구분해 보고했다.
5. **피드백:** 사용자가 작은 결과를 확인할 수 있게 제시하고, 다음 작업의 방향을 맞춘다.
